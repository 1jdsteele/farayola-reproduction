RUN 032 — Reweighing + Adversarial Debiasing + Reject Option Classification
(Re + AL + ROC), COMPAS

PURPOSE
Execute and diagnose:

Reweighing (Re)
    -> Adversarial Debiasing / Adversarial Learning (AL)
    -> Reject Option Classification (ROC)

REFERENCE RUNS
- Run 027: Re + AL
- Run 030: AL + ROC

KEY IMPLEMENTATION FINDING
Run 027 established experimentally that:

Re + AL = AL

for every controlled seed, including byte-identical:
- binary prediction SHA256
- continuous AL score SHA256
- confusion matrices
- metrics

Source inspection explains this behavior:
legacy AIF360 AdversarialDebiasing.fit() does not consume
dataset.instance_weights.

Reweighing changes instance_weights but leaves features and labels unchanged.

HYPOTHESIS FOR RUN 032
Because:
1. Re + AL produces the same predictions and scores as AL, and
2. ROC receives the same continuous scores and same test labels as Run 030,

Run 032 is expected to reproduce Run 030 exactly.

This equality is measured explicitly rather than imposed.

REWEIGHING
AIF360 Reweighing is applied to the training BinaryLabelDataset.

Required checks:
- instance weights change
- weights remain finite and positive
- features remain unchanged
- labels remain unchanged
- protected race values remain unchanged

The reweighted BinaryLabelDataset is passed directly to AL.

No manual sample_weight argument is supplied.

AL SETTINGS
Paper-faithful:
- adversary_loss_weight = 0.2
- num_epochs = 50
- batch_size = 128
- debias = True

Library default:
- classifier_num_hidden_units = 200

The hidden-unit parameter is inherited from AIF360 0.6.1 and is not
explicitly passed.

CRITICAL PRE-ROC CONTROL
The Re -> AL stage must reproduce frozen Run 027 exactly for every seed in:
- prediction SHA256
- continuous score SHA256
- confusion matrix
- all five metrics
- score diagnostics

ROC SETTINGS
- metric_name = "Equal opportunity difference"
- low_class_thresh = 0.3
- high_class_thresh = 0.8
- num_class_thresh = 100
- num_ROC_margin = 50
- metric_ub = 0.05
- metric_lb = -0.05

ROC uses the continuous AL scores.

TEST-SET CALIBRATION
ROC is fit using:
- true labels from the evaluation test set
- Re+AL predictions/scores from that same test set

and is evaluated on that same test set.

This preserves the established repository-style postprocessing pathway and
its conventional test-set calibration/evaluation leakage.

CRITICAL FINAL CONTROL
Run 032 is compared directly against frozen Run 030 for every seed in:
- ROC classification threshold
- ROC margin
- number of predictions changed
- final prediction SHA256
- confusion matrix
- all five final metrics

If those all match, then the nominal Re stage has no downstream effect on
the complete Re -> AL -> ROC pipeline.

METRICS

- predictive equality / false-positive-rate difference

REPRODUCIBILITY
Run 032 is executed twice as independent Python processes, A and B.

Freeze only after exact A/B repeatability is confirmed.
